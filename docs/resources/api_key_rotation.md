# Resource (rootly_api_key_rotation)

Rotates the token of the API key that the provider is authenticated with, and exposes the new token as the sensitive `token` attribute.

A rotation happens when the resource is created, and again whenever any argument changes (for example `triggers`). The new token is only returned once, at rotation time, so store it securely (for example in a secret manager) and then update the provider configuration to use it.

Important notes:

- **The API key must be the one the provider is authenticated with.** The Rootly API only lets a key rotate itself. Rotating any other key returns an error.
- **Use one `rootly_api_key_rotation` per provider configuration.** Every instance rotates the same key. If two instances share a provider configuration, the second rotation invalidates the first one's token. Terraform can't detect this at plan time, so keep it to one instance (no `count` or `for_each`) per provider configuration.
- **The provider keeps using the old token for the rest of the apply.** It doesn't switch to the new token mid-run. If `grace_period_minutes` is `0`, or the grace period feature isn't enabled for your organization, the old token stops working immediately, and every later API call in the same run fails. That includes refreshes of other resources. Keep the default grace period, and switch the provider to the new token before it ends.
- **Switch the provider to the new token before the next rotation.** The grace period only covers the token that was just replaced. If the provider is still configured with an older token when the key is rotated again, that older token stops working immediately.
- **Destroying this resource doesn't revoke or change any token.** It only removes the resource from the Terraform state.

## Example Usage

```shell
# Rotate the API key the provider is authenticated with every 30 days.
resource "time_rotating" "rootly_api_key" {
  rotation_days = 30
}

resource "rootly_api_key_rotation" "this" {
  # Must be the ID of the API key the provider is authenticated with.
  api_key_id = "00000000-0000-0000-0000-000000000000"

  # Keep the previous token valid for an hour, so the new token can be rolled out.
  grace_period_minutes = 60

  triggers = {
    rotation = time_rotating.rootly_api_key.id
  }
}

# Store the new token, then point the provider at it.
resource "aws_secretsmanager_secret_version" "rootly_api_token" {
  secret_id     = "rootly-api-token"
  secret_string = rootly_api_key_rotation.this.token
}
```

## Schema

### Required

- `api_key_id` (String) The ID of the API key to rotate. This must be the API key the provider is authenticated with.

### Optional

- `expires_at` (String) The expiration date of the new token, in RFC 3339 format (for example `2027-01-01T00:00:00Z`), up to 5 years in the future. Defaults to 90 days after rotation if omitted. Changing this value rotates the API key again. The actual expiration date is exported as `token_expires_at`.
- `grace_period_minutes` (Number) How many minutes the previous token stays valid after rotation, from 0 to 1440. Defaults to `30`. Only applies when the grace period feature is enabled for your organization. Setting it to `0` invalidates the previous token immediately, which breaks the rest of the current apply because the provider is still authenticated with the previous token. Changing this value rotates the API key again.
- `triggers` (Map of String) Arbitrary map of values. Changing any of them rotates the API key again. Use it, for example, with `time_rotating` from the `hashicorp/time` provider to rotate on a schedule.

### Read-Only

- `grace_period_ends_at` (String) The time when the previous token stops working. Null if the grace period feature isn't enabled for your organization.
- `token` (String, Sensitive) The new API key token issued by the rotation.
- `token_expires_at` (String) The expiration date of the new token.
